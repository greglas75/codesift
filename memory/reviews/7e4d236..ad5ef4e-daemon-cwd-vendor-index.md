## Verdict

**APPROVE.** Five defects, all of them exposed by moving from stdio to the
shared daemon and all invisible before it for the same structural reason: the
stdio server inherited the client's project directory, so `process.cwd()`
happened to be right. The daemon runs from `/`.

## What changed

**1. The daemon could not auto-resolve a repo at all.** Every call omitting
`repo` answered `Repository "local/" not found`. Fixed by carrying the caller's
directory with the request (AsyncLocalStorage), sourced from `roots/list` where
supported and from a `?cwd=` pinned in the connection URL otherwise — Claude
Code answers roots with `-32601 Method not found`, so the URL is what actually
works. Getting `roots/list` delivered took four attempts, each failing as an
indistinguishable timeout.

**2. Scoped searches silently returned nothing.** A ripgrep `--glob` with a
`/` anchors to ripgrep's working directory, not the search path. `*.ts` worked
and `src/**/*.ts` did not, so it read as a glob-syntax problem. Worse, the
tool's own timeout hint recommends the broken form.

**3. The response cache was dead for every auto-resolved call.**
`cacheKeyFor` runs before `wrapTool`, so `args["repo"]` is still absent and the
`process.cwd()` fallback decided the key.

**4. `vendor/` was indexed.** 97,323 files across 6 repos; tgm-mobi and Mobi3
were 89% Composer dependencies and sat exactly on the 50,000-file cap, so
first-party source was being evicted — silent incompleteness, not just
slowness. Graph tools timed out at 90s, which is how it surfaced.

**5. The cap truncated silently.** Raised 50,000 -> 200,000 and now reported on
the result (`file_limit_hit`); previously it went to stderr alone.

## Findings from the adversarial pass

**A1 — the exclusion auto-heal had no lower bound. [accepted, fixed]** Raised
independently by two providers. The bypass fired on excluded-fraction alone,
which describes the OLD index and says nothing about whether the NEW walk
succeeded; a truncated walk on a vendor-heavy repo would have been accepted and
the merge would have wiped the missing files. Now also requires the walk to be
plausible against the non-excluded remainder.

**A2 — daemon still falls back to `process.cwd()`. [accepted with rationale]**
When neither the URL nor roots yields a directory the fallback resolves to
`local/` and produces a misleading "run index_folder first". Reachable only via
a hand-edited config now that `setup --http` always writes `?cwd=`, so the extra
failure path costs more than the case it covers.

## Verification

Full suite 363 files / 5194 tests green. Verified against the running daemon
(cwd `/`): a roots-less client with `?cwd=` resolves correctly, without it the
same call fails. Reindexed the three affected repos — tgm-collect
11,622 -> 1,577, Mobi3 50,000 -> 9,509, tgm-mobi 50,000 -> 9,448 — and
`detect_communities` on tgm-collect went from exceeding the 90s timeout to 0.2s.

Measured before deciding what else to exclude, across all 169 local indexes:
`Pods`, `bower_components`, `target`, `third_party`, `vendored`, `externals`,
`Carthage` — zero files. Nothing further is warranted.
