## MUST-FIX

**R-1 [MUST-FIX] A failed chmod leaves a token-bearing file world-readable, silently**

- File: `src/cli/setup/fs.ts:45` (same shape at `src/cli/setup/fs.ts:52`, `src/cli/service.ts:307`)
- Confidence: 92/100 — CRITICAL from the adversarial pass, then verified against the source
- Evidence: `writeFile(path, content, { mode: SECRET_FILE_MODE })` sets the mode only when the
  file is CREATED — open(2) ignores `mode` for an existing path. So for a file that is already
  0644, the `chmod` on the next line is the only thing that restricts it, and `.catch(() => {})`
  discards every failure, not just the non-POSIX case the comment names. The file's own comment
  states "the explicit chmod below covers the rewrite case" — the swallow disables exactly that
  case.
- Why it matters here: this is not theoretical. Setting up the shared daemon on burst-i9 earlier
  today produced a systemd unit at `-rw-r--r--` containing `CODESIFT_HTTP_TOKEN`, readable by the
  `gha` CI user; it had to be chmod'ed by hand. A token that grants read access to every indexed
  repository over the tailnet is precisely what these commits set out to protect.
- Fix: distinguish "this filesystem has no modes" from "I was not allowed to change them".
  Swallow only the unsupported-operation errnos and surface the rest — at minimum a warning
  naming the path, since a silent failure here reads as success.
- **RESOLVED** in `src/cli/owner-only-file.ts` (this run). Both call sites now go through
  `writeOwnerOnlyFile` / `writeOwnerOnlyFileSync`, which tighten an existing file BEFORE the
  new token is written (so the credential never lands at the old mode), tolerate only
  ENOSYS/ENOTSUP/EOPNOTSUPP, and otherwise stat the file: already owner-only means the chmod
  was redundant, anything group- or world-accessible raises with the path and the actual mode.
  Covered by `tests/cli/daemon-token-transport.test.ts` — a real un-chmod-able file
  (`chflags uchg`, darwin) plus errno/mode truth-table cases that run everywhere. Verified by
  mutation: reverting the throw fails the test.
