# Code review — the tool timeout now cancels its work (f43869e..550f12d)


## Verdict

**APPROVE.** One defect with an unusually large blast radius, plus the
composition fix the adversarial pass earned.

## What changed

`withTimeout` answered `timed_out` and left the handler running. From one day
of telemetry, against a 90-second budget:

    scan_secrets      median   20ms   p90 50.6s   max 5.1 HOURS
    find_references   median  663ms   p90 14.3s   max 5.0 hours
    search_patterns   median   26ms   p90  0.7s   max 4.9 hours
    audit_scan        median  521ms   p90  6.7s   max 1.0 hour

Each ran for hours after its caller gave up, and it compounds: an agent given
`timed_out` retries with a narrower scope, so the abandoned scan runs alongside
its own replacement. This is the mechanism behind the CodeSift processes seen at
240-360% CPU all day and a load average above 600 — which in turn made the test
suite fail on timeouts and made measuring the daemon impossible.

`search_text` was the exception (max 121s) because it already had its own wall
clock with a real `controller.abort()`. Everything else trusted a wrapper that
cancelled nothing.

The wrapper now aborts a controller on expiry and publishes the signal through
the ambient request context, so ripgrep and the walkers can act on it without
~150 handler signatures growing a parameter.

## Findings from the adversarial pass

**A1 — signals were selected, not composed. [accepted, fixed]** Three of four
top findings, independently. `options.signal ?? currentAbortSignal()` let a
caller's own controller shadow the timeout; `signal: controller.signal`
overwrote whatever the context already held, so a nested `withTimeout` disarmed
the outer one. Both now use `AbortSignal.any`, so the first to fire wins.

No CRITICAL findings; 8 WARNING / 3 INFO, the rest either covered by the
composition fix or pre-existing behaviour outside this diff.

## Deliberate choices

- The context is EXTENDED, not replaced. Replacing it would drop the client's
  working directory and send every daemon-served call back to resolving repos
  against `/`. Covered by a test, since the type system would not catch it.
- `currentAbortSignal()` returns undefined outside a request, so CLI and test
  callers keep their existing behaviour rather than getting a signal that never
  fires.

## Verification

365 files / 5202 tests green. The cancellation itself was verified by
falsification — removing the `controller.abort()` line fails the suite — and
the composition by a test that aborts the outer signal while the inner budget
is still running.
