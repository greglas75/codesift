## Findings fixed — this range's own code

**R-1 [CRITICAL, cursor-agent, high]** `src/register-tool-groups/core/symbols.ts:218`
`scan_coverage: sink.coverage ?? { status: "complete" }`. The sink is filled only when the scan
completes, so an unset sink means an early exit or a throw — and the default claimed a full scan
exactly then. In the field whose purpose is to admit uncertainty, the fallback asserted certainty.
Now `unknown`, with the result marked inconclusive.

**R-2 [WARNING, codex-5.3, high]** `src/tools/plan-turn/stale-index.ts:42`
A matching git HEAD was reported as `current`. Uncommitted, staged and untracked changes do not
move HEAD, so an index predating them compares equal and was labelled verified. `current` now
requires HEAD match AND a clean worktree; dirty gives `unknown/worktree_dirty`, unreadable state
gives `unknown/worktree_state_unknown` rather than being assumed clean. A working session has a
dirty tree nearly always, which is when an agent most needs to distrust an empty result.

## Findings recorded, not patched — another session's SQLite fix (b7245f8)

Not this reviewer's change, and each fix is a design decision rather than a typo. Backlogged.

**R-3 [WARNING, high]** `src/storage/sqlite-index-store.ts:308` — opening a v1 index upgrades it
to v2 and reports success, but the symbols v1 dropped stay missing until a full reindex. A
consumer sees a migrated database and treats it as complete. Suggested: persist a
`requires_reindex` flag until the source has been re-parsed.

**R-4 [WARNING, high]** `src/storage/sqlite-index-store.ts:194` — dropping the PRIMARY KEY makes
`symbols.id` non-unique, so id lookup returns an unspecified "first" row. SQLite row order is not
an identity contract; the answer can change after a vacuum or rebuild. Suggested: a genuinely
unique key, or return all matches.

**R-5 [WARNING, high]** `src/storage/sqlite-index-store.ts:593` — the paged load yields to the
event loop between pages, so another request can insert or delete rows mid-traversal and the
resulting CodeIndex can mix database states. Suggested: one read transaction on a dedicated
connection.
