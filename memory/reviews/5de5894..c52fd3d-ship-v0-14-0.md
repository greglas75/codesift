## Findings and disposition

The cross-provider review covered the complete range in 11 chunks, then the fix diff and the tail
of the single large ADR separately. It found four introduced correctness/documentation defects,
all fixed before this artifact:

1. A stream error during backpressure could leave chunk persistence waiting forever for `drain`.
   Both chunk writers now reject on `error` and wait for stream completion before rename.
2. `prune` could replace a healthy same-name registry owner, then delete a newly rescued owner while
   removing the stale entry. Rescue now requires one unambiguous candidate and preserves the
   rightful live owner.
3. `repair-registry.mjs` selected same-name owners by filesystem iteration order. It now applies the
   same live-owner and uniqueness rules, with direct tests for both blocked and successful repair.
4. An unreadable unregistered SQLite index could be swept as garbage. Indeterminate databases are
   now protected and reported for manual inspection.

The ADR's contradictory claims about immediate disk savings versus rollback retention, and about
SQLite being both rejected and deferred, were corrected. It now specifies deterministic dual-format
precedence, whole-file checksum scope, atomic migration and the opt-in post-retention cleanup that
actually realizes disk savings.

Remaining adversarial notes were downgraded with evidence: a canonical `.index.json` registry path
is deliberately logical and `sqlitePathFor()` derives the existing `.db`; stream errors are checked
at the start of every loop iteration and by `finished()`; duplicate meta keys are excluded by the
SQLite primary key; and treating a definitively absent root as stale is the documented purpose of
`prune`.
