## Findings fixed

**R-1 [CRITICAL, adversarial on 8f6671f] Bearer token written onto a plaintext remote URL**
`src/cli/setup/mcp.ts:151` — `setup --http --host <remote> --token <t>` produced
`http://<remote>/mcp` plus an `Authorization: Bearer` header. Requiring a token does not make a
routable plaintext endpoint safe: the token is static and replayable, and whoever captures it can
call every tool, exposing every indexed repository on that daemon.
**Fix (906e674):** refused unless `--scheme https` or an explicit `--insecure-transport`
acknowledgement that the link is already encrypted below HTTP (tailnet/VPN/SSH tunnel). The code
cannot distinguish a tailnet address from a public one, so it has to be stated. Loopback exempt.

**R-2 [CRITICAL, 2 providers, on my own fix] Loopback exemption bypass**
`src/cli/setup/mcp.ts:72` — `isLoopbackHost` used a prefix test, so `127.attacker.example` and
`127.0.0.1.attacker.example` were exempted from the guard; those names resolve wherever their
owner points them. `127.0.0.1@attacker.example` was the same class via URL userinfo — `URL`
connects to `attacker.example` while the string reads as local. A bypass of the guard, inside
the guard.
**Fix (28139df):** loopback decided by `isIP` — literal addresses only, incl. `::ffff:127.0.0.1`;
`isIP` returns 0 for any hostname, so the class falls through to the guard. Hosts containing
`@`, `/`, `?`, `#` or whitespace are rejected at both the URL builder and the guard. Six tests
target the vectors rather than the happy path.

**R-3 [WARNING, adversarial on 8f6671f] IPv6 hosts produced an unparseable URL**
`src/cli/setup/mcp.ts:100` — string concatenation produced `http://::1:7077/mcp`, so an IPv6 or
tailnet-IPv6 daemon could not be configured at all. Built with `URL` now, IPv6 literals bracketed.
