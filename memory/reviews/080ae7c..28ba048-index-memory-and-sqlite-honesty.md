## Findings — all MUST-FIX applied

**R-1 [MUST-FIX] The read snapshot covered only half the index.**
`src/storage/sqlite-index-store.ts:770` — `repo`/`root` were read on the shared connection before
the transaction opened, and `created_at`/`updated_at`/`extractor_version`/`workspaces` after it
committed. A concurrent `saveIndexSqlite` in either gap pairs metadata from one revision with rows
from another. Worse than an obviously stale index, because every field is individually valid.
*Fixed*: all meta reads moved inside the same transaction. Found by adversarial (codex-5.3, CRITICAL).

**R-2 [MUST-FIX] The lossy-migration marker was cleared by any whole-index write.**
`src/storage/sqlite-index-store.ts:540` — the commit message claimed "an incremental write only
refreshes the file it was given", but `src/storage/index-store.ts:632` (`enqueueIndexMutation`)
folds a single-file edit into a full `saveIndexSqlite`, and `index_folder` reuses cached symbols for
unchanged files. Rewriting every row is not re-reading every file.
*Fixed*: clearing gated on `sourceComplete`, set by `folder-indexer` only when `filesToParse.length
=== files.length`, defaulting to false. Over-warning is cleared by a reindex; silence is cleared by
nothing. Found by adversarial (codex-5.3).

**R-3 [MUST-FIX] The marker informed nobody.**
`src/storage/sqlite-index-store.ts:554` — written, exported, and read by no production caller. The
honesty mechanism was write-only, which is the same defect it existed to fix one layer down.
*Fixed*: rides on the index as `CodeIndex.lossy_migration`; `index_status` reports that
`symbol_count` is a floor, not a count. Found independently by adversarial and BEHAV-1.

**R-4 [MUST-FIX] `getSymbol`'s throw escaped into two search tools.**
`src/tools/symbol-tools.ts:747`, `:810` — `find_and_show` and `get_context_bundle` read the id back
off a BM25 hit they already hold; neither catches. Failing a whole search because its top hit sits
in a minified bundle makes the collision a worse answer than the substitution it replaced.
*Fixed*: `resolveSearchHit` falls back to the hit; a caller-supplied id still throws. Found by
adversarial (claude).

**R-5 [MUST-FIX] `getSymbols` did last-write-wins on the same input.**
`src/tools/symbol-tools.ts:318` — two entry points in one file disagreeing about a colliding id,
one throwing and one silently substituting.
*Fixed*: both refuse, via a shared `AmbiguousSymbolIdError`. Found by CQ-2 and adversarial.

**R-6 [MUST-FIX] The footprint tally counted UTF-16 code units, not bytes.**
`src/storage/sqlite-index-store.ts:740` — V8 stores a string at one byte per character only while it
fits Latin1, so CJK/Cyrillic/emoji text was under-counted by ~half: the one direction the
calibration comment rules out, on the field that is 45% of the footprint.
*Fixed*: `Buffer.byteLength` on prose fields. Found by BEHAV-3 — **not** by the adversarial pass.

**R-7 [RECOMMENDED] `openReadConnection` leaked a handle when the PRAGMA threw.**
`src/storage/sqlite-index-store.ts:686` — the guard its sibling `openIndexDb` documents, missing
here only because this connection is deliberately not cached, so the caller's `finally` had nothing
to close. *Fixed*. Found by BEHAV-2.

**R-8 [RECOMMENDED] Eviction re-summed the whole cache per iteration.**
`src/storage/index-store.ts:234` — O(n²) against `CODESIFT_MAX_CACHED_INDEXES`, which has a floor
and no ceiling. *Fixed*: running total, recomputed fresh per call. Found by BEHAV-4 and adversarial.

**R-9 [RECOMMENDED] `hasMeasuredFootprint` was exported for nothing but its own test.**
*Fixed*: removed; the test now pins the same contract numerically. Found by CQ-3.

## Findings rejected, with reasons

- **"The fallback estimate lets JSON-backed indexes exceed the budget."** Unreachable: `readIndex`
  caches only on the SQLite path — `loadJsonIndex` returns directly and never enters `indexCache`.
- **"`filesToParse.length === files.length` does not prove no cache reuse."** Reuse is the exact
  complement of `filesToParse`: a file is either parsed this run or its symbols are kept. Equality
  therefore does imply no reuse. A file that fails to parse contributes nothing rather than stale
  rows, which is a different and visible problem.
- **"The running eviction total can drift if a cached index is mutated in place."** `loadIndex`
  hands out `copyIndex(...)`, mutation paths run `invalidateIndexCache`, and `total` is recomputed
  from scratch on every `cacheIndex` call — drift cannot accumulate across calls, and nothing
  mutates inside the loop.
- **"`lossy_migration` should be value-aware, not presence-aware."** Only `"1"` is ever written and
  the key is deleted to clear. Accepting `"false"` as a stored value would invite the opposite bug.
