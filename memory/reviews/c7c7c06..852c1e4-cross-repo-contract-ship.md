# Cross-repo contract tools ship review

## Outcome

APPROVE. The historical `cross-repo-contract-tools.ts` entry point is now a thin,
stable facade over responsibility-focused adapters, matching, group resolution,
types, and outbound-call parsing modules. Public exports remain compatible.

## Behavior review

The multi-provider adversarial passes found contract-classification defects that
were reproduced with regression tests and fixed before approval:

- consumers from different repositories no longer collapse during deduplication;
- root prefixes cannot partially match parameter-first routes;
- required and optional Next.js catch-all routes retain distinct matching rules;
- custom resolver methods are compared case-insensitively;
- consumer file read failures are surfaced as warnings;
- fetch method inference is bounded to its own call and ignores comments, strings,
  nested option objects, and regex literals;
- quoted method keys and methods promoted by inline object spreads are recognized;
- absolute, protocol-relative, relative, and interpolated URL paths preserve the
  route evidence needed by the matcher.

No unresolved correctness or security blocker remains in the reviewed range.
Suggestions to resolve methods assembled through arbitrary helper calls or dynamic
spreads require semantic/AST evaluation and remain parser-capability enhancements,
not regressions introduced by this change.

## Structure and quality

The facade preserves the original import boundary while each extracted module has
one primary responsibility. CodeSift reported no secrets, breaking changes,
coupling gaps, dead code, or known bug patterns. Its filename-based coverage check
does not associate the new modules with the existing umbrella test, but all modules
are exercised through `cross-repo-contract-tools.test.ts` and the dedicated resolver
and lexer suites.

`sniffFetchMethodFromWindow` is intentionally conservative but now has high
cyclomatic complexity because it performs a bounded JavaScript lexical scan. A
future change should extract that scanner into a small token-state module; this is
an advisory maintainability item and is covered by the regression suite.

## Review-light report

No ship-blocking defect remains. Error handling is explicit for per-file resolver
failures, malformed fetch calls cannot borrow later methods, and all loops remain
bounded by source length. The changed API surface is backward-compatible.

## Coverage-check report

Changed production behavior is covered by direct unit tests and end-to-end group
contract tests. Boundary cases added during review include catch-all cardinality,
root-prefix matching, resolver warning propagation, dynamic URL origins and query
strings, quoted and nested method properties, inline spreads, regex braces, and
unterminated fetch calls.
