## Verdict

**APPROVE.** Touches the server core, so it was verified against the running
daemon rather than in-process tests alone, and against the two invariants a
migration like this most plausibly breaks.

## What changed

**1. Embeddings stopped re-computing on every process start.** Content hashes
lived in a module-level Map that was never persisted, so a fresh process loaded
the vectors, found no hashes, and re-embedded everything: 4,178,280 symbols
across 1,587 repos — 16.5 hours on the M5 GPU, 93 on CPU — on every MCP server
start, and a server starts once per session. The real daily delta is ~500
symbols, 7 seconds. The hash now travels on the same ndjson line as its vector,
so the two cannot drift and it costs no extra file or read.

**2. Stateless HTTP serving (MCP 2026-07-28, SDK v2).** The session map made
every daemon restart fatal to every connected client — `no valid session` until
someone reconnected by hand, on every `service install --force`. With no
protocol-level session there is nothing to invalidate, and any request can land
on any instance, which is the precondition for a second process or a remote
host without a shared session store.

The benefit does not wait for clients: `legacy: 'stateless'` is the default and
Claude Code 2.1.220, still negotiating 2025-11-25, is served statelessly today.

**3. A correction.** Two comments claimed Claude Code answers `roots/list` with
`-32601 Method not found`. Probed directly, it does not — it declares
`roots: {listChanged: true}` and returns its workspace directory. The -32601 in
the daemon log belonged to another client; the log does not attribute lines, and
reading them as Claude Code's was an assumption presented as a measurement.

## Findings from the adversarial pass

**A1 — the roots fallback disappeared with the session. [accepted, addressed]**
Sole CRITICAL, and correct: a client connecting without `?cwd=` had no
directory source at all, resolved to `local/`, and surfaced as
`Repository "local/" not found. Run index_folder first.` — pointing an agent at
re-indexing when the fault is a missing URL parameter.

Restoring a roots lookup is the wrong shape here: statelessness has no session
to have learned the answer once, so it would be a server->client round-trip on
every tool call. The failure is now named, with both fixes in the message, and
fires only inside a request context so CLI and tests are untouched.
