## Rejected (checked against the code)

- "reusableChunkManifest loads the chunk file, not the manifest": `loadChunkManifest(filePath)` maps a chunk path to `<hash>.chunk-index.json` itself.
- "manifest.model is never checked before reuse": `reusableChunkManifest(indexPath, model)` gates every main-generation reuse; the checkpoint checks its own header model.
- "acquireLock returns held:false for a lock this process holds": deliberate — the caller reports "this process is already embedding" and runs without a checkpoint.
- "release() frees a lock it may not hold": `releaseLock` returns unless `heldHere` has the path.
- "fresh scratch file never deleted on failure": `acquireReserved`'s outer `finally` unlinks it.
- "takeTakeoverLock cannot retry after clearing": iteration 0 clears, iteration 1 links (covered by "clears a takeover lock its dead holder left behind").
- "embed-gate test shares slotDir across parallel tests": vitest runs the cases of one file sequentially.
- Hash extraction `name.slice(0, indexOf('.'))`: same prefix as the manifest's `<hash>.chunk-index.json`; dotless names are never generation files.
- Non-EEXIST fs errors reported as busy: deliberate degrade to "no checkpoint this run", never a failed run.

## Accepted residuals

- Two takers clearing one DEAD holder's takeover lock at once can both proceed — needs a process to die inside a few ms of file operations while two others contend (documented in file-lock.ts).
- A slot held by a live but wedged process blocks that slot until the process exits; the request's own timeout starts only after the slot is taken.
- Cloned vectors/chunks describe the donor's version of files that differ until this checkout's run replaces them by content hash.
